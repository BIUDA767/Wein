# 2026-10-30 — engine single-writer lock + packaging

## Leader lock (new, safety-critical)
- Postgres advisory locks are PER SESSION. My first cut cached one pool client and
  short-circuited `if (leaderClient) return true`, so a second engine in the same
  process also got `true` and could double-trade. Fixed: every acquire uses its own
  dedicated connection (`getPool().connect()`), and `acquireLeaderLock()` returns a
  numeric TOKEN (or null). `holdsLeaderLock(token)` / `releaseLeaderLock(token)`.
- Engine stores `private leader: number|null`. `init()` re-runs when brokers change,
  so acquisition is guarded by `if (this.leader === null)` — otherwise the second
  init tries to re-lock against its own connection, fails, and NULLS a held lock
  (this exact bug made smoke fail with "not the active trading leader").
- Lock key `0x50485253`; `acquireLeaderLock(key)` is parameterizable so the DB
  integration test can use its own key `0x7e57c0de` and not collide with a live API.
- Enforced in BOTH order paths: autonomous `tick()` and `manualOrder()`.

## Connectivity resilience (second pass)
- Found a real spec gap: `runTick()` tracked `brokerConnected` but never re-checked it, and
  `refreshBroker()` only runs when `!this.active || !this.market` (stays truthy), so a mid-run
  drop could never recover. The autonomous path also never blocked on a dead broker.
- Added `checkConnectivity()` (throttled 5s, uses `verifyConnection`): on loss sets
  `brokerConnected=false` + critical notification + `broker.disconnected` audit; on recovery
  sets it true, runs `reconcile()`, notifies, writes `broker.reconnected`. Paper always verifies,
  so paper trading is never blocked. New-order guard added in `runTick()`.
- Refactored inline deps into `execDeps()`.
- Test `tests/connectivity.test.ts` injects an outage by overriding the adapter's
  `verifyConnection`. IMPORTANT: it must create a real active paper broker first, or it
  returns early and passes falsely. Suite now 92 tests / 9 files.

## Paper simulator durability (third pass)
- User-visible bug: placed a paper order via the UI, restarted the API, and the order stayed
  `open` forever. Root cause: `PaperAdapter` keeps `balance` + `positions` in an in-memory Map;
  a restart reset the balance to the starting value and lost every open contract. Worse, the
  balance shown in the UI drifted from realized P&L because the simulator's balance and the
  DB's realized profit were independent.
- Also found: `settleOpenOrders` fast-path returns early when the adapter has `settleExpired`,
  so the DB-based fallback never runs for paper. Fixing durability makes the fast path correct.
- Fix: `paperRestoreState(brokerId, accountId, mode)` in core repo derives realized P&L from
  settled orders and open contracts from open orders; `PaperRestore` is threaded through
  `createAdapter` and `BrokerManager.buildAdapter/loadActive/reload(mode)`. Balance =
  starting + realized - open stake.
- Also changed `PaperAdapter.getOrder` to return `null` (not `{status:'settled'}`) for an
  unknown contract, so an orphan is treated as unresolved rather than a silent win.
- Verified live: orphan settled (+4.50 on a 5.00 stake = 0.9x), and restored balance was
  exactly 10000 + realized(-5.5) = 9994.5.
- Suite now 93 tests / 9 files; smoke 43/43.
