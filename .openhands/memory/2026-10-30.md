## Expensive lessons
- The web app is **inlined** `@phirst/core`; after a core change rebuild core *and* web and
  restart `next start`, or you get stale-bundle bugs.
- Build web with `NODE_ENV=production npm run build -w @phirst/web` — the sandbox's global
  `NODE_ENV=development` breaks `next build`.
- `apps/web` has **no** `.env.local` here; env lives in the repo-root `.env` (root `.gitignore`
  ignores `.env`). `next.config.mjs` proxies `/api/*` to `PHIRST_API_INTERNAL ?? :12001`.
- Start services: `npm run start:api` (root, tsx) and `npm run start -w @phirst/web` from
  `apps/web`. Logs to `.run/` (gitignored).
- Postgres runs in container **`phirst-pg`** (user `phirst`, db `phirst`). Fresh DB →
  `ownerExists:false`, so run `/api/auth/setup` first.
- `case` globs in bash do **not** support `\|` alternation — a smoke assertion using it
  silently never matches. Use a plain substring.

## Incident — "the link is dead" (2026-10-31 01:37 UTC)
**Symptom:** the public work-1 URL returned 200 and the app HTML loaded, but the page was
**completely unstyled** (looked dead/broken to the owner).
**Root cause:** running `NODE_ENV=production npm run build -w @phirst/web` during pre-push
verification replaced `apps/web/.next/` **while `next start` was still serving**. The running
server kept the old build manifest in memory and emitted HTML referencing
`/_next/static/css/8666ab…css`, a file that no longer existed on disk (it had been replaced by
`f807cb…css`). That CSS request returned **400**, so every style was missing. HTML/JS/API all
returned 200, which is why a naive reachability check said "healthy".
**Diagnosis that worked:** compare the CSS href in the *served* HTML against the files in
`apps/web/.next/static/css/`. A mismatch = stale server.
**Fix:** `kill <next-server pid>` then restart `npm run start` from `apps/web`. CSS then 200s.
**Rule:** never run a production build while `next start` is serving. Rebuild first, *then*
restart. A 200 on `/` is not proof the app is healthy — check a static asset too.

4. `npm run migrate` (applies 0001 + 0002).
5. `npm run start:api` → wait ~12s → `/api/health`.
6. From `apps/web`: `npm run start` → wait ~14s. `apps/web/.next` survived, so no rebuild needed.
7. Fresh DB means `ownerExists:false` → re-run `POST /api/auth/setup` to recreate the owner,

8. `(setsid nohup ./scripts/wein-supervise.sh >/dev/null 2>&1 &)` to survive a process death.

## Telegram linking bug (fixed, commit `1300d92`)
- Symptom: bot always replied "This chat is not linked", however many fresh codes were sent.
- Cause: `/api/telegram/link-code` issued the code with the literal string `"owner"` as
  `user_id`. `telegram_links.user_id` is a FK to `users(id)`, so the `/start` insert threw
  a foreign-key violation. The poll loop caught it, logged a warn, and the chat saw only
  the generic "not linked" message.
- Fix: bind the code to `RequestContext.userId` (the authenticated owner's real uuid) and
  wrap the link insert so a rejection is logged, audited and reported to the chat.
- Lesson for this codebase: any column named `*_id` is likely a real FK. Never store a role
  or a placeholder ("owner", "system") in one. Invariant 45.
- Diagnostic that found it fast: `grep -i telegram .run/api.log` showed the FK error that
  the UI never surfaced.

## Session 2026-10-30 (later) — audit for real bugs; three safety fixes

Audited for dead buttons/stubs, dishonest capability reporting and unhandled 500s.
Findings: none dead (Admin.tsx's "not implemented" pill is intentional); provider catalog
honestly gates on `implemented`; edge cases return proper 400/503. But three real
correctness bugs surfaced, all fixed and verified live.

**BUG-A (critical, found this session): emergency stop was not sticky.**
`Engine.start()` set `state="running"` unconditionally, so the UI Start/Resume button —
and Telegram `/resume` — silently cleared an engaged emergency stop and re-armed trading.
Same class: `pause()`, `stop()` and `setMode()` all end in a non-emergency state, so any
of them could clear it too. Fix: `start()/pause()/stop()/setMode()` now refuse while
`state==="emergency"`; only `resetEmergency()` clears it. `pause`/`stop` now return
`{ok,message}` and the routes + Telegram handlers surface the real reply (previously
Telegram `/pause` and `/stop` always said "done"). AGENTS.md invariant 46.

**BUG-B: `maxExposure` silently ignored for fixed-expiry contracts.** Open contracts live
in `orders`, not `positions` (empty for these), so exposure read as 0 and nothing was ever
vetoed. Fix: pure `currentExposure(openOrderAmounts, positionSizes)` in
`packages/core/src/risk/engine.ts` = max(sum orders, sum positions) — max, not sum, to avoid
double-counting a mirrored position+order. Wired into engine `riskContext()`. Invariant 47.
Reproduced empirically: maxExposure 100, three 60-unit orders all approved before; after,
order 2 is reduced to 25 and order 3 is vetoed.

**BUG-C: `consecutiveLossLimit` configurable but never enforced.** Fix: `settleExpired`
re-checks the streak after settlement; new pure helper `lossStreakBreached(n, limit)`
(limit 0 disables) triggers `pause()`. Verified live: limit 1, second losing 5s contract
paused the engine. Invariant 48.

**BUG-D: voice accent unvalidated.** `PUT /api/phirst/voice` accepted `"klingon"` → 200.
Fix: `ALLOWED_ACCENTS` exported from `@phirst/ai`; route validates voice/rate/pitch/accent
against the same list the client offers. Invariant 49.
