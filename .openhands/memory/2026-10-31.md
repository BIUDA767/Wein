## Session 2026-10-31 (later) — Deriv OAuth 2.0 one-tap connect

Goal: replace manual PAT entry with "Connect Deriv" one-tap OAuth, end to end.

- **Flow**: Authorization Code + PKCE (S256). `packages/brokers/src/deriv-oauth.ts` builds the
  authorize URL and does the form-encoded token exchange. `code_verifier` is generated server
  side, encrypted into `oauth_states`, and never sent to the browser. Token exchange happens
  only in the API process.
- **Single-use state**: `consumeOAuthState` uses `UPDATE ... RETURNING` so it reads and marks
  consumed atomically — two concurrent callbacks cannot both exchange the same code. Verified
  live: first callback reached Deriv's real token endpoint and got `invalid_client` (proving
  the outbound call is real), the replay got `invalid_state`.
- **No refresh token from Deriv** (confirmed from their docs). `expires_in` is recorded at
  connect; a passed expiry is reported as `expired` before an API call fails. OAuth tokens are
  sent WITHOUT the `Deriv-App-ID` header (PAT only); an OAuth 401 is a reconnect condition.
- **Active-account selection** (`packages/core/src/db/active-account.ts`): connecting never
  silently replaces the active account; it only claims an empty slot, prefers a demo account,
  and a manual switch with open exposure requires confirmation (`409 requiresConfirmation`).
- **`credentials_enc` leak fixed**: `/api/brokers/active` was returning the raw `brokers` row
  (ciphertext included). Added `toPublicBroker` and applied it to the health payload.
- **Live verification** (API on 12001, real Postgres, real Deriv endpoints):
  `config` → `configured:false` + `requiredEnv` when unset; `start` → `503` when unset, real
  `auth.deriv.com` URL when set; callback → `302` with `deriv=error&reason=invalid_client`
  (bad code), `invalid_state` (replay/unknown), `cancelled` (user denied); `activate` →
  `200` with the new selection. UI: `?deriv=connected` shows the toast and auto-opens the
  brokers panel, then cleans the URL.
- Tests: +6 DB-integration cases (OAuth state single-use / unknown / expired / concurrent
  race, active selection preserved, demo preferred) and +8 connection cases. Suite 204 / 17.
  Note: `db-integration` needs `DATABASE_URL=$TEST_DATABASE_URL npm run migrate` first, and
  `oauth_states.user_id` FKs to `users`, so the test seeds a real user row.
- AGENTS.md invariants 54–60 added.

  app dashboard (DERIV_APP_ID=1089). Until then the button honestly reports "setup needed".

## Deriv connection — diagnosis for the owner (same day, follow-up)

Answering "how do I make the Deriv connection functional?" by isolating the failure:

- `DERIV_APP_ID=1089` is Deriv's **public example id**, not an app registered to our token.
  Both auth paths fail for the same reason: a PAT REST call with `Deriv-App-ID: 1089` returns
  **401 "Invalid application"**. The PAT (68 chars, `pa…`) is never validated because the app
  id is rejected first — so we cannot yet tell whether the token itself is good.
- **Both** PAT and OAuth require an app id registered under the Deriv account that owns the
  token. There is no anonymous/self-serve OAuth client; registration happens while signed in
  to a real Deriv account (api.deriv.com App Builder / dashboard). The UI banner is honest.
- No silent failure: `DERIV_OAUTH_CLIENT_ID` unset ⇒ `POST /api/deriv/oauth/start` → **503**
  with `requiredEnv`; `/api/deriv/oauth/config` → `configured:false`.
- **Fixed a real deployment defect:** `PHIRST_WEB_ORIGIN` was `http://localhost:12000`, so the
  default OAuth redirect was `localhost` and could never complete from the public link. Set it
  to the public host; redirect is now
  `https://work-1-kznopodrculyuhfn.prod-runtime.all-hands.dev/api/deriv/oauth/callback`
  (this exact string must be registered at Deriv).
- **API env quirk:** `npm run start:api` does NOT load `.env` (no dotenv in the API process).
  Must `set -a; . ./.env; set +a` in the shell before starting, or env edits silently no-op.
- Legacy `wss://ws.derivws.com/websockets/v3` is unreachable from here; the adapter's
  `wss://api.derivws.com/trading/v1/options/ws/public` opens fine.
- Hosts: work-1 = web app (root 200), work-2 = raw API (root 404, `/api/health` 200).
- Reset paper state: `TRUNCATE orders, positions, equity_snapshots, agent_verdicts,
  notifications, audit_log; UPDATE accounts SET balance=10000;` then restart the API — the
  engine's `restorePaperState` rebuilds balance from startingBalance + realizedPnl − openStake.
  (A raw `UPDATE accounts.balance` alone is ignored; an orphan open `positions` row kept
  equity at 9890.)
- Smoke: `PHIRST_PASSWORD="WeinOwner2026!" npm run smoke` → 48/49. The lone FAIL is a
